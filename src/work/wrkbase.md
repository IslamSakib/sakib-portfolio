## Why did I build Wrkbase?

I kept seeing the same problem on client teams: daily operations spread across five or six tools that don't talk to each other. If your team lives in that, you know how much time goes on switching between them. Wrkbase puts them in one system for small businesses, agencies and remote teams.

## What does the software do?

- Tasks with automatic time tracking, so nobody has to remember a timer
- Attendance, leave, performance, payroll and payslips
- Team chat alongside the work
- An AI agent that plans operational work, shows each step, waits for approval, then executes, with every action logged
- Role-based access and audit logging

## What's on the website?

- Product and feature pages, and a page for the AI agent
- Free tools: overtime, PTO accrual, time card, employee cost and turnover calculators
- Comparison pages, pricing, a blog, a help center, a glossary and a changelog

## What does this project show?

This is custom development, not WordPress. I designed the product, built the software, and built the site it's sold from. If you need a SaaS product built end to end, this is the proof I've done it.

## How did the SaaS development go?

- I built sign-in first, so everything after it knew who the user was
- Time tracking is automatic. I removed manual timers because people forget to start them
- Tasks sit behind sign-in on purpose: a person who hasn't signed in can't start work, so attendance takes care of itself
- The AI agent came last, on top of data the product already had

## What was the bug worth describing?

The agent started telling users it was unavailable. The API was answering and the model's replies were fine. The fault was earlier: the agent wasn't being triggered, and a render delay made it look like a failure. I fixed the trigger. It's a good example of why an AI feature needs someone who can follow the whole path, not only the model call.
