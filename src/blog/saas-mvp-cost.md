SaaS MVP cost follows scope, not ambition. The price is set by how many different screens, user roles and integrations the first version has. Cut those to the one flow users must complete, and the cost falls fast.

## What sets the price

1. **User roles.** One kind of user is simple. Admin, staff and customer roles each add screens and rules.
2. **Billing.** Plans, limits and payment flows are real work, so many MVPs start with one plan.
3. **Integrations.** Each connection to email, payments or another tool is its own piece of work.
4. **The admin side.** You need to see what users do. A simple dashboard is enough at first.
5. **Design.** Designing the screens properly costs less than redoing them after launch.

## A first version I built

Wrkbase is my own team platform. It started with sign-in and tasks, then added time tracking, attendance, payroll and an AI agent that asks before it acts, in that order. Each step shipped before the next began.

## How to keep it small

- Write down the one thing a user must be able to do.
- Move everything else to a "later" list.
- Launch to a small group, watch what they do, then choose the next feature from that.
